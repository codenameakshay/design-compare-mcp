Compare a region. Refine the detail.

We extracted reference frames and paired them with clone screenshots. Regional compare_designs diagnostics guided calendar geometry and log-card styling, separating local differences from changes in scroll position.

For the log-card opening and a number change, selected frame sequences helped us inspect changes in motion energy and timing with compare_motion. Similar energy does not establish matching animation.

The useful lesson

Select the same state first, then compare it. Extracting matching frames was a manual step here; keeping frame selection separate from scoring made the diagnostics easier to interpret.

Visual scores do not establish gesture correctness. Taps, swipes and navigation need separate behavioral checks.

That preparation step now has a tool. extract_video_frames takes a short window from a local recording and returns absolute frame paths, source timestamps and a saved manifest. Extraction timestamps support manual preparation; comparison does not itself establish matched actions or cadence.

Recording context and comparison limits

These edits follow different routes and timings, so playback is independent. The original includes only settings, calendar settings and the drink editor. The clone demo predates the build-4 tap fix and does not show the latest build.

The development comparisons used matching regions and selected interactions, not these complete edits. For a repeatable comparison, retain each source timestamp and crop, and sample the same action at a comparable cadence and duration. Read motion_status first; static or unreliable captures are inconclusive. No whole-app fidelity score is claimed.

Color

weight 0.20

Projects every pixel onto a fixed color lattice. Combines maximum sliced mass distance across 64 directions with source-density-scaled soft rare-color coverage in chroma-compressed Lab proxy units. Each direction uses the same source-query density correction for own and target occupancy.

weakness not CIEDE2000 or 3D optimal transport. Equal-histogram spatial swaps are invisible. Soft coverage does not prove exact absence. Color-shift findings summarize certified unmatched mass on both sides, not any recoloring operation. Failure to certify absence does not prove presence. The independent color review records a close-hue reversal as recolored mass grows. Local qualification and independent PASS cover the frozen v2 contract; full-project checks and hosted CI remain pending. No universal accuracy or monotonicity claim.

Content

weight 0.15

A contrast-adaptive detector matches the reference's blocks to yours by IoU. Missing or extra blocks become findings.

weakness coarse; region boxes wobble.

Typography

weight 0.15

Text lines by morphology, compared on amount and scale. Not OCR, not font identity.

weakness misses a wrong font; null when no text.

Spacing

weight 0.15

Outer margins and vertical rhythm from major blocks, each within a tolerance.

weakness coarsest; null on sparse views.

Where it can mislead you

Motion energy. Similar motion energy can hide different paths or timing. Static and unreliable captures are inconclusive. Read motion_status.
Color ranking. The old dark-library dataset showed little color-ranking signal. Palette errors can still matter in a single-theme UI.
Typography ≠ font. Amount and scale, not font family or weight.
One-shot animations. An animation that ends before sampling can be missed. Inspect the frames and status.
Ignore chrome. Status bars and OS chrome: pass ignoreRegions as [x, y, w, h] in original reference pixels.
Capture URLs. capture_frames accepts http and https only. Set DESIGN_COMPARE_ALLOWED_ROOTS to restrict local file reads and capture output paths, not network access.

FAQ

Frequently asked questions

What problem does this solve?

It adds repeatable measurements and diagnostic images to visual review. The output helps identify differences; it does not replace visual or behavioral checks.

What do I feed it?

Two local images, a reference and a candidate. widget mode for a tight crop, screen mode for a full view. Optional ignoreRegions in original reference pixels. For motion, two frame sequences from capture_frames using http or https URLs. For recorded video, extract a bounded local window with extract_video_frames, then review timestamps, sampling completeness and matching action before comparison.

How is the score computed?

Applicable numeric dimensions contribute to the weighted geometric mean, with scores clamped to 1–100 and weights renormalized. Inspect failed and non-applicable dimensions before interpreting the aggregate. If no dimensions have numeric scores, the aggregate is 0, not a usable comparison.

Can I ignore a status bar?

Yes. Pass ignoreRegions as [x, y, w, h] boxes in original reference pixels. Finding boxes come back in the canonical 768 canvas. Use the returned canvas mapping to translate.

Is the number accurate?

The published human-label correlations describe an earlier pipeline on 26 pairs. They are not a current accuracy estimate for the reliability changes. Synthetic regression checks test specific cases, not broad perceptual accuracy.

Can I calibrate it for my own UI?

Yes. Drop (reference, candidate, your 0–100 label) pairs into calibration/ and run scripts/calibrate.py.

Why TypeScript and Python?

TypeScript speaks MCP and drives headless-Chrome capture; a resident Python worker does the vision, so the heavy imports load once, not per call.

Is it safe to run?

It reads local paths you pass. Set DESIGN_COMPARE_ALLOWED_ROOTS to restrict local file reads and capture output paths. These are path restrictions, not process or network isolation. capture_frames accepts http and https; use trusted URLs. Recording extraction runs local FFmpeg, so use trusted recordings and keep the decoder updated.
